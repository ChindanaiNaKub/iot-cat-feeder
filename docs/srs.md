# SRS เครื่องให้อาหารแมวอัตโนมัติ

สถานะเอกสาร: ฉบับร่าง 0.9 · 30 ตุลาคม 2569
อ้างอิง: `docs/proposal.md`

เอกสารนี้อธิบายความต้องการของระบบ ยังไม่บอกวิธีสร้าง (วิธีสร้างอยู่ใน `docs/sdd.md`)

## 1. ขอบเขตระบบ

ระบบประกอบด้วยบอร์ด NodeMCU v3 ที่ให้บริการหน้าเว็บเองใน Wi-Fi วงเดียวกัน ต่อกับ servo หนึ่งตัวที่ควบคุมฝาถังอาหาร ระบบไม่พึ่ง cloud และไม่ต้องมีเซิร์ฟเวอร์ภายนอก ยกเว้นการขอเวลาจาก NTP

```text
มือถือ ──Wi-Fi──> NodeMCU ──PWM──> Servo ──> ฝาถังอาหาร
                     │
                     └──> NTP (pool.ntp.org) สำหรับเวลาจริง
```

## 2. ผู้ใช้

| ผู้ใช้ | สิทธิ์ | ใช้ทำอะไร |
|---|---|---|
| เจ้าของ | เปิดหน้าเว็บใน Wi-Fi วงเดียวกัน | ดูสถานะ สั่งให้อาหาร |
| แมว | ไม่มีสิทธิ์ | เข้ามาใกล้เครื่อง |
| ผู้ดูแลระบบ | อัปโหลดเฟิร์มแวร์ | ตั้งค่าเวลาและจำนวนมื้อ |

## 3. ความต้องการเชิงหน้าที่

ระดับความสำคัญใช้ MoSCoW คือ Must, Should, Could

| ID | ความต้องการ | ระดับ | เกณฑ์ยอมรับ |
|---|---|---|---|
| FR-01 | ระบบต้องให้อาหารเมื่อผู้ใช้กดปุ่มบนหน้าเว็บ | Must | กดปุ่มแล้วฝาเปิดภายใน 1.5 วินาที |
| FR-02 | ระบบต้องปิดฝาเองภายใน 1 วินาทีหลังเปิด | Must | ทดสอบ 50 รอบ ไม่มีรอบใดฝาค้าง |
| FR-03 | ระบบต้องให้อาหาร 3 เวลาต่อวันตามเวลาจริงจาก NTP | Must | เวลาที่บันทึกตรงกับเวลาที่ตั้งไว้ไม่เกิน 1 นาที |
| FR-04 | ระบบต้องบันทึกจำนวนครั้งที่ให้อาหารวันนี้ เวลาล่าสุด และแหล่งที่มา | Must | หน้าเว็บแสดงค่าตรงกับที่ทดสอบ |
| FR-05 | ระบบต้องรีเฟรชสถานะบนหน้าเว็บเองทุก 2 วินาที | Must | เปิดหน้าค้างไว้ ค่าเปลี่ยนเองเมื่อสั่งจากเครื่องอื่น |
| FR-06 | ระบบต้องไม่ให้อาหารซ้ำในเวลาเดียวกันหลายรอบ | Should | ให้อาหารด้วยมือ 5 ครั้งรัวๆ ฝาเปิดทีละรอบ ไม่ค้างซ้อน |
| FR-07 | ระบบต้องให้อาหารเองเมื่อตรวจพบแมวเข้ามาใกล้ 60 เซนติเมตร | Should | ทดสอบกับแมวจริง 20 ครั้ง ทำงานถูกไม่น้อยกว่า 16 ครั้ง |
| FR-08 | ระบบต้องไม่ให้อาหารเกินเพดานที่ตั้งไว้ต่อวัน | Should | ตั้งเพดาน 3 ครั้ง แล้วสั่งครั้งที่ 4 ต้องถูกปฏิเสธและแจ้งบนหน้าเว็บ |
| FR-09 | ระบบต้องวัดระดับอาหารคงเหลือในถัง | Could | ถังเต็มอ่านค่าต่างจากถังว่างอย่างชัดเจน |
| FR-10 | ระบบต้องตวงน้ำหนักอาหารต่อมื้อเป็นกรัม | Could | ชั่งด้วยตาชั่งเทียบ คลาดเคลื่อนไม่เกิน 15 เปอร์เซ็นต์ |
| FR-11 | ระบบต้องเก็บประวัติการให้อาหารข้ามการรีบูต | Could | ตัดไฟแล้วเปิดใหม่ ประวัติยังอยู่ |

ความเห็นต่อลำดับความสำคัญ FR-07 ถึง FR-11 ขึ้นกับของที่สั่ง ถ้าของมาไม่ทันก่อน 2 พฤศจิกายน ให้ตัดออกและย้ายไป Future Work ในเอกสาร Conclusion

## 5. ส่วนต่อประสาน

### 5.1 ส่วนต่อประสานกับผู้ใช้

หน้าเว็บหนึ่งหน้า แสดงห้าแถวข้อมูล และมีปุ่มเดียว

| ข้อมูลที่แสดง | ค่า | แหล่งที่มา |
|---|---|---|
| สถานะฝา | เปิดอยู่ หรือ ปิดสนิท | `feeder.open` |
| ให้อาหารวันนี้ | จำนวนครั้ง | `feeder.countToday` |
| ครั้งล่าสุด | เวลาและแหล่งที่มา | `feeder.lastTime`, `feeder.lastSource` |
| เวลาบนเครื่อง | ชั่วโมง นาที วินาที | `clockText()` |
| ตั้งเวลาไว้ | เวลาทั้งสามมื้อ | `scheduleText()` |

### 5.2 ส่วนต่อประสาน HTTP

| วิธี | เส้นทาง | คำขอ | คำตอบ |
|---|---|---|---|
| GET | `/` | ไม่มี | HTML หน้าเดียว |
| GET | `/status` | ไม่มี | JSON ตามหัวข้อ 5.3 |
| POST | `/feed` | ไม่มี body | `{"ok":true}` |
| อื่นๆ | ใดๆ | ไม่มี | 404 พร้อมข้อความ |

### 5.3 รูปแบบ JSON ของ `/status`

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `open` | boolean | ฝาเปิดอยู่หรือไม่ |
| `count` | จำนวนเต็ม | จำนวนครั้งที่ให้อาหารวันนี้ |
| `last` | ข้อความ | เวลาล่าสุดรูปแบบ HH:MM หรือ `-` |
| `source` | ข้อความ | `เว็บ` หรือ `ตั้งเวลา` |
| `time` | ข้อความ | เวลาบนเครื่องรูปแบบ HH:MM:SS หรือ `--:--:--` |
| `schedule` | ข้อความ | เวลาที่ตั้งไว้คั่นด้วย `·` |
| `ip` | ข้อความ | IP ของบอร์ด |
| `rssi` | จำนวนเต็ม | ความแรงสัญญาณ Wi-Fi หน่วย dBm |

### 5.4 ส่วนต่อประสานกับฮาร์ดแวร์

| อุปกรณ์ | ขา | ทิศทาง | สถานะ |
|---|---|---|---|
| Servo SG90 | D5 (GPIO14) | ออก (PWM) | ต่อแล้ว |
| HC-SR04 ตรวจจับแมว | ยังไม่กำหนด | เข้าและออก | รอของ |
| HC-SR04 วัดระดับอาหาร | ยังไม่กำหนด | เข้าและออก | รอของ |
| HX711 และ load cell | ยังไม่กำหนด | เข้าและออก | รอของ |
| LED บนบอร์ด | D4 (GPIO2) | ออก | ใช้ทดสอบเท่านั้น |

ขา ECHO ของ HC-SR04 จ่าย 5V แต่ GPIO ของ ESP8266 รับได้ 3.3V ต้องมีตัวแบ่งแรงดันหรือใช้รุ่นที่จ่าย 3.3V
